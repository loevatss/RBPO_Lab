# Лабораторная работа №6

## Создание цепочки сертификатов и настройка HTTPS

### Цель работы

Изучить процесс создания цепочки сертификатов, настройку HTTPS для Spring Boot-приложения и организацию безопасного CI-процесса с использованием GitHub Actions и Secrets.

---

### Ход работы

1. **Создание цепочки сертификатов**  
   С помощью утилиты `keytool` была создана цепочка сертификатов из трёх звеньев:

   - корневой центр сертификации **AuroraRootCA**;
   - промежуточный центр сертификации **PolarIntermediateCA**;
   - серверный сертификат **nebulaServerTLS**.

   Во всех сертификатах в поле `OU` указан идентификатор студента (номер студенческого билета). Сертификаты подписаны последовательно, сформирована корректная цепочка доверия.

2. **Настройка HTTPS в Spring Boot**  
   Было создано хранилище ключей `server.jks`, содержащее приватный ключ сервера и полную цепочку сертификатов.  
   В файле `application.properties` выполнена настройка TLS:
   ```properties
   server.port=8443
   server.ssl.enabled=true
   server.ssl.key-store=classpath:server.jks
   server.ssl.key-store-type=JKS
   server.ssl.key-store-password=${SSL_KEYSTORE_PASSWORD}
   server.ssl.key-alias=nebulaServerTLS
   ```
3. **Добавление сертификата в доверенные**
   Корневой сертификат AuroraRootCA был добавлен в хранилище доверенных корневых центров сертификации Windows. После этого браузер корректно принимает сертификат без предупреждений безопасности.

4. **Настройка непрерывной интеграции (CI)**
   В репозитории GitHub создан workflow .github/workflows/ci.yml, реализующий процесс непрерывной интеграции:

сборка проекта;

запуск тестов;

упаковка приложения;

публикация артефакта.

Пароль keystore и другие чувствительные данные хранятся в GitHub Secrets, что предотвращает утечку приватных ключей и паролей.
